# Security policy

Thank you for helping keep SightPress and the people who use it safe.

## Supported versions

SightPress is before version 1.0. Security fixes go into the latest release of each package (`core`, `skeleton`,
`module-interface`, `theme-interface`). Please update to the latest release before you report a problem.

## Report a vulnerability

**Never report a security problem in a public issue, discussion or pull request.**

Report it privately, in whichever way suits you:

- on GitHub: open the *Security* tab of the repository, for example
  [core's security page](https://github.com/sightpress/core/security), and choose **Report a vulnerability**; or
- by email to <security@sightpress.org>, in any accessible format.

Please tell us:

- what the problem is and what someone could do with it;
- how to reproduce it, step by step;
- the version of SightPress and, if you know them, the PHP version, the database and the web server.

## What happens next

1. We acknowledge your report within **5 working days**.
2. We check the problem, tell you what we found and agree a date to publish a fix.
3. We fix it, release the fix and publish a security advisory. With your permission, we thank you by name.

Please give us a reasonable time to fix the problem before you tell anyone else about it.
